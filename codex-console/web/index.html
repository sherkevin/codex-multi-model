⓪ 运行模式：自定义（中转）↔ 原生（ChatGPT 登录）↔ 出厂（未登录）

自定义=走我们的中转 + 第三方模型 + 免登录绕过；原生=还原 ChatGPT 账号登录、model/provider 退回原生；出厂=把配置交还给「刚装好、还没登录」的官方 Codex，给第三方切号器（如 Cockpit Tools）接管用。切换只动模式专属键（model / model_provider / review_model / model_catalog_json / model_reasoning_effort / model_providers）+ auth.json，你的 hooks / mcp_servers / plugins / features 等共享设置三态都不碰；改前自动备份、可来回切，且往返逐字节不变。切完需重启桌面 App 生效。

后端模式 & 中转（model → 真实 provider，透明路由）

下表是中转 此刻真实生效 的路由（取自 /v1/routes）。Codex 的 model_provider 是单值：跨 provider 或含 translate 模型时必须经中转统一分发；只有「全部模型同一 provider 且都 passthrough」才能直连、不经中转。

① Provider（真实上游：base_url · AK 变量）

每个 provider = 一个真实上游。AK 只填变量名（值在「密钥」卡写，绝不进配置文件）。

② Model（显示名 · 描述 · 可见性 · 默认档 · 走哪个 provider）

每个模型选它的 provider（用哪家的额度）与 模式：passthrough=上游原生 Responses；translate=上游只有 chat、需中转翻译。显示名/描述/可见性/默认档写进模型目录（改后需重启桌面 App）。

默认模型与思考档（config.toml 顶层）
密钥 AK（上游真实 Key）

写入 ~/.codex/router-secrets.env（权限 600），绝不进 config.toml、绝不回显明文。改完需重启中转生效。

绕过账号登录（auth.json = apikey 模式）

Codex 登录门只校验 auth.json 处于 apikey 模式且有任意非空 key；占位串即可过门，真实鉴权由中转各 AK 完成。被 codex logout 或升级重置后点修复。
